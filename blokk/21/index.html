Projektfejlesztés I.: adatmodell, backend, API

A jóváhagyott terv első mérföldköve. A záró projekted repójába bemásolod a backend-csomagot – egy működő, rétegzett FastAPI-vázat SQLite-tal és cserélhető LLM-mel –, és átalakítod a saját projektedre. A 2. órán mindenkivel haladási konzultáció.

Minden réteg egy dolgot tud

FájlRétegMit csinálsz vele?

src/app/llm_port.pyLLM-portkész: ál-LLM (tesztek, LLM_AL=1) és valódi LLM ugyanazzal a felülettel – a 22. blokkban ide jön az ágens

Miért rétegek?

A szolgáltatás szerver és kulcs nélkül tesztelhető; az adatbázis és az LLM kicserélhető; párban külön fájlokban dolgozhattok. A mintában (Házirend-kalauz) a „forrás nélkül nem válaszolunk” szabály a szolgáltatásban él – nem az API-ban és nem az SQL-ben.

Kipróbálás kulcs nélkül

LLM_AL=1 mellett az ál-LLM válaszol. A szerver a python -m uvicorn app.api:app --app-dir src --reload paranccsal indul, a végpontokat a http://127.0.0.1:8000/docs oldalon próbálhatod ki.

  1. 1

    A csomag bemásolása

    Töltsd le a csomagot (Code → Download ZIP, vagy a Teams Fájlok fülről), és másold a záró projekted repójának gyökerébe, felülírással. Négy fájl frissül (.gitignore, ci.yml, requirements.txt, tests/conftest.py), a többi új – a terved megmarad.

    Expand-Archive ..\bolyai-labs-21-backend.zip ..\csomag
Copy-Item ..\csomag\bolyai-labs-21-backend\* . -Recurse -Force
pip install -r requirements.txt
python -m pytest -q

    A GitHubról letöltött ZIP-ben a mappa neve bolyai-labs-21-backend-main – a parancsban ezt írd. 3 piros: ezek a te munkád.

  2. 2

    Adatmodell: schema.sql és modellek.py

    A PROJEKTTERV.md 5. fejezetéből: legalább két tábla, egy kapcsolat. Minden táblához olyan Pydantic-modell, amilyet a kliens küld és kap. Ami egyik történethez sem kell, az most kimarad.

  3. 3

    adatbazis.py, szolgaltatas.py, api.py

    A „pelda” függvények helyére a sajátjaid. Legalább 1 POST és 2 GET végpont, köztük egy GET /…/{azon}, amely nem létező elemre 404-et ad. Legalább egy végpont az LLM-et is megkapja (llm: LLMPort = Depends(get_llm)) – ha a mérföldköved szerint még nem kell, egy egyszerű, ál-LLM-mel tesztelt hívás is elég.

  4. 4

    Saját tesztek

    Írd át a tests/test_sajat_api.py-t: legalább 3 teszt a saját végpontjaidra, az elfogadási feltételeidből. A fixture memóriabeli adatbázist és ál-LLM-et ad – kulcs és szerver nélkül.

  5. 5

    Kipróbálás a /docs oldalon

    $env:LLM_AL="1"
python -m uvicorn app.api:app --app-dir src --reload

    A böngészőben: http://127.0.0.1:8000/docs. Próbáld ki az összes végpontot, egy hibás kérést és egy nem létező azonosítót is.

  6. 6

    ADR, haladási napló, push

    Másold le a docs/adr/0000-sablon.md-t 0001-….md néven, és írd le egy döntésedet (pl. rétegek vagy egy fájl? SQLite vagy JSON?). Töltsd ki a HALADAS.md 21. blokkos részét: állapot (zöld / sárga / piros), elkészült, következő lépés, akadály, kérdés.

A leggyakoribb hibák

ModuleNotFoundError: app

A repó gyökeréből futtasd: python -m pytest és python -m uvicorn app.api:app --app-dir src.

ModuleNotFoundError: llm_kliens a szerver indításakor

Ne uvicorn …-t írj, hanem python -m uvicorn …-t – így a repó gyökere is a keresési útban van.

sqlite3.ProgrammingError: … thread

Maradjon meg az Adatbazis konstruktorában a check_same_thread=False.

A 404-es teszt 500-at kap

A szolgáltatás dobjon NincsIlyen kivételt, az API pedig alakítsa HTTPException(status_code=404)-re.

A 422-es teszt 201-et kap

A POST-modellben legyen legalább egy kötelező mező (alapérték nélkül).

IntegrityError: FOREIGN KEY constraint failed

Nem létező szülőre hivatkozol. A szolgáltatás előbb ellenőrizze, hogy a szülő létezik (különben 404).

A „pelda” teszt még piros, pedig mindent átírtam

Keress rá kisbetűvel is a src/app fájljaiban, a schema.sql-ben és a tests/test_sajat_*.py-ban – a megjegyzésekben is.
