1. Határérték-elemzés

Az azonos módon kezelt bemenetek egy ekvivalenciaosztályt alkotnak: osztályonként egy teszt elég. A hibák a határokon sűrűsödnek (< vagy ≤?), ezért a határra és mindkét oldalára is kell teszt.

2. Szintetikus tesztadat

Előnyök: nincs benne személyes adat (GDPR), annyi készül, amennyi kell, célzottan tartalmazza a határeseteket, és seeddel reprodukálható: rng = random.Random(42). Korlát: csak azt tartalmazza, amire gondoltunk.

3. Hibás modulok predikciója

Kódmetrikákból (méret, bonyolultság, változások, szerzők, tesztlefedettség) gépi tanulással jósoljuk, melyik modulban lesz hiba – és azt teszteljük először. Ugyanaz, mint a 3. blokkban: ritka címkénél a felidézés számít.

Technikai lépések

Indulás és beadás

0/5
  1. 1

    Saját repó és klónozás

    A sablon linkjét a mérés elején kapod meg a Teamsben. Use this template, név medior- + osztálykód + sorszám, Public. Aztán:

    git clone https://github.com/<felhasznalonev>/medior-13b-07.git
cd medior-13b-07
code .
  2. 2

    Környezet

    py -3 -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python -m pytest ellenor -q

    Az elején mind a 4 CI-teszt piros.

  3. 3

    A feladatok

    Minden fájl elején, a docstringben ott a részletes leírás: f1_hatarertekek.py, f2_szintetikus.py, f3_hibas_modulok.py (F3 és F4), F5_ERTEKELES.md. Kezdd azzal, amelyiket a legjobban tudod.

  4. 4

    Ellenőrzés menet közben

    python -m pytest ellenor -q
python f3_hibas_modulok.py

    A teszt neve megmondja, melyik feladat kész már. Az F3 fájlja futtatva kiírja a modelled eredményét.

  5. 5

    Push a 40. percig

    git add .
git commit -m "meres: Medior rangemelő mérés"
git push

    Ami nincs a GitHubon, az nem számít. Az Actions fülön a Medior mérés futásban minden zöld teszt 2 pont. Aztán a repó linkje a Teams-feladatba.
