Egy ágens vagy egy csapat?

Miért csapat?

Független ellenőrzés (a Tesztelő a specifikációból dolgozik, nem a kódból), rövidebb és élesebb promptok, szűkebb jogosultság. Az ára: több hívás, több idő, és a lánc elején elkövetett hiba végigfut a csapaton.

Jó szerepleírás

Egyértelmű cél (mit ad át a csapatnak), világos határ (mit NEM csinál), ismert bemenet (kitől kap) és kimenet (kinek, milyen formában), és csak a munkájához kellő eszközök.

Feladatkártya #14 · 2. óra · CrewAI szerepkör kiosztás

Világos szerepek, szűk jogosultságok

„Fejlesztési vezetőként szeretnék egy ágenscsapatot, amelyben mindenkinek világos a szerepe: a Kutató tényeket gyűjt, a Tervező specifikál, a Programozó kódol, a Tesztelő ellenőriz – és mindenki csak azokhoz az eszközökhöz fér hozzá, amelyek a munkájához kellenek.”
Hogyan tesztel a CI kulcs nélkül?

A CI valódi CrewAI-t futtat, de valódi modell helyett egy ál-LLM-szerverrel. Ez a rendszerpromptból látja, melyik szerep kérdezi: a Programozónak egy fajl_ir eszközhívással válaszol, így a CrewAI tényleg elmenti a fájlt. A teszt azt is ellenőrzi, hogy a context továbbadja-e az előző ágens munkáját, és hogy mindenki pontosan a kiosztott eszközeit látja-e.

Hat lépés · VS Code-ban

Lépésről lépésre

Pipáld ki, amit már megcsináltál: a böngésződ megjegyzi, hol tartasz.

0/6
  1. 1

    Saját repó és Python 3.12-es környezet

    A sablonrepón: Use this template, név csapat- + osztálykód + sorszám, Public. A CrewAI-hoz Python 3.12 kell, és a telepítés percekig tart – indítsd el minél előbb:

    git clone https://github.com/<felhasznalonev>/csapat-13b-07.git
cd csapat-13b-07
py -3.12 -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python -m pytest -q

    16 piros, 11 zöld (a zöldek a kész kódot ellenőrzik). Ha a pip nagyon lassú: pip install uv, aztán uv pip install -r requirements.txt.

  2. 2

    A szerepek: config/agents.yaml

    Mind a négy szerepnél: role (ki ő), goal (mit ad át a csapatnak – legalább egy rendes mondat), backstory (hogyan dolgozik, és mit nem csinál). Az 1. órai szerepkártyákból dolgozz. Utána nézd meg, mi lett belőle:

    python csapat.py --szerepek

    tests/test_szerepek.py: zöld.

  3. 3

    A feladatlánc: config/tasks.yaml

    Minden feladatnál description (mit csináljon), expected_output (pontosan milyen formájú eredményt), és context (kinek a munkáját kapja meg). A kutatás leírásában maradjon benne a {feladat}; a kód és a teszt feladat nevezze meg a dij.py, test_dij.py fájlt és a fajl_ir eszközt. tests/test_feladatok.py: zöld.

  4. 4

    A jogosultságok: config/jogosultsagok.yaml

    Öt eszköz van: tudastar_kereses, wiki_kereses, szamol, fajl_olvas, fajl_ir. Mindenki csak azt kapja, ami a szerepéhez kell. Írni csak annak lehet, akinek tényleg menteni kell. Ezután zöld a tests/test_csapat.py is: a csapat egy ál-LLM-mel végigfut, a Programozó elmenti a dij.py-t.

  5. 5

    Az indoklás: SZEREPEK.md

    Töltsd ki a szerepkör-mátrixot (mit csinál, mit nem, milyen eszközt kap és miért), és válaszolj két kérdésre: miért nem egyetlen ágens? Mi történik, ha a lánc elején hiba van? Mind a 27 teszt zöld.

  6. 6

    Élő futás (ha van kulcsod) és push

    python csapat.py "díjszámító függvény a havi tokenhasználatból"
git status
git add config SZEREPEK.md
git commit -m "feat: ágenscsapat szerepkörei (feladatkártya #14)"
git push

    Az eredmény a munkaterulet/kimenet/ mappában lesz. A tapasztalatot írd a SZEREPEK.md végére: melyik ágens lépett ki a szerepéből, és mit írnál át a leírásán? A .env nem lehet a git status listájában.
